# Phase 15.4: Zero Dead Zones - Context

**Gathered:** 2026-03-24
**Status:** Ready for planning

<domain>
## Phase Boundary

Eliminate dead zones between keyboard keys so every pixel of the keyboard surface resolves to a key. Touches in visual gaps (background padding between keys, side margins, row boundaries) must fire the nearest key's action with correct audio and haptic feedback. Issue #56 tracks this with full research context (AOSP LatinIME, Apple patent, Fleksy, 3 failed approaches).

</domain>

<decisions>
## Implementation Decisions

### Touch surface strategy
- Architecture: per-key DragGestures stay as primary touch handlers; the existing catch-all DragGesture on the ZStack `.background()` handles touches that fall in visual gaps
- The overlay catches gaps only -- it does NOT replace per-key gestures
- Incremental approach (from 3 failed attempts in issue #56):
  1. **Step 1:** Add version/build to logs (issue #58) to prevent stale build confusion
  2. **Step 2:** Add temporary touch logging to the existing catch-all to verify it fires in gap areas
  3. **Step 3:** Improve the catch-all's nearest-key resolution (ProximityGrid from git history)
  4. **Step 4:** Validate with systematic tap testing, then remove temporary logs
- NEVER remove working DragGestures until the catch-all is confirmed working via logs

### Nearest-key resolution
- Rectangular grid model: Y position determines row, X position determines key within row
- Simple row clamp for row-boundary touches (no cross-row awareness needed -- gap is only ~11pt)
- Full keyboard width coverage: touches in side margins (rowSidePadding: 3-5pt) resolve to edge keys (left margin -> first key, right margin -> last key)
- Improve existing `handleDeadZoneTap()` logic rather than building a new system

### Long-press & drag compatibility
- Catch-all = tap only: fires the nearest key's single-tap action (insert char, space, single delete, toggle shift)
- No long-press behaviors from gaps: accent popup, delete repeat, and space trackpad only work when touch starts ON a key
- SwiftUI gesture priority already handles this: per-key DragGestures win when touch starts on a key; background gesture only fires for touches starting in gaps
- No extra guards needed beyond existing `deadZoneTapFired` flag

### Validation approach
- Version/build number added to log output (issue #58) as prerequisite
- Temporary touch coordinate logging in catch-all: "gap-touch: (x,y) -> key 'E'"
- Systematic UAT: 20+ gap taps (between adjacent keys, between rows, side margins, corners) -- all must resolve to correct key with audio/haptic
- Touch logging is TEMPORARY -- removed after validation passes (not kept in production)

### Claude's Discretion
- Exact implementation of ProximityGrid (reuse from git history commits 83767f6..f201d1a or rewrite)
- Whether to pre-compute key rectangles at layout time or compute on each touch
- Log format and level for temporary touch logging
- How to structure the version/build logging (issue #58)

</decisions>

## Existing Code Insights

### Reusable Assets
- `handleDeadZoneTap(at:rowWidth:)` in KeyboardView -- existing catch-all with row/column resolution logic, needs improvement for edge cases and margins
- `KeyMetrics` enum -- all spacing constants (keyHeight, rowSpacing, keySpacing, rowSidePadding, keyCornerRadius) needed for grid computation
- `DeviceClass` enum -- 3 device classes with breakpoints, already used for adaptive layout
- `KeyDefinition.widthMultiplier` -- per-key width multiplier used in unitKeyWidth calculation
- Git history ProximityGrid code (commits 83767f6..f201d1a) -- may be reusable for improved resolution

### Established Patterns
- HStack(spacing: 0) with inset backgrounds for visual gaps -- means key frames are already adjacent, dead zones are in the padding/margin areas
- `.contentShape(Rectangle())` on all keys -- extends hit area to full frame
- `deadZoneTapFired` flag pattern -- prevents multiple catch-all fires per gesture
- Per-key DragGesture(minimumDistance: 0) for touchDown feedback -- must not be disrupted

### Integration Points
- ZStack in KeyboardView.body -- catch-all gesture on `.background()` of the VStack
- `insertCharacter()` pipeline -- catch-all calls this for character key resolution
- All special key actions (delete, space, return, shift, globe, emoji, layer switch) -- catch-all dispatches via switch on `targetKey.type`
- `PersistentLog` -- for temporary touch logging during validation
