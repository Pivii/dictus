## Summary

Implemented the touch forwarding view pattern to eliminate all dead zones on the UIKit keyboard.

## What was built

**KeyboardTouchForwardingView** — a transparent overlay that intercepts ALL touches on the keyboard surface and routes them to the nearest button by squared Euclidean distance. Once a touch begins on a button, all subsequent move/end/cancel events go to the SAME button (preserves accent drag, space trackpad, delete repeat).

**Forwarded touch handlers** — all button classes (LetterKeyButton, ShiftKeyButton, DeleteKeyButton, SpaceKeyButton, ReturnKeyButton, GlobeKeyButton, EmojiKeyButton, LayerSwitchKeyButton, AdaptiveAccentKeyButton) received `handleForwardedTouchDown/Moved/Up/Cancelled` methods that extract their existing touch logic. Original touch overrides remain as fallback.

**KeyboardContainerView rewiring** — ForwardingView added as topmost subview. All UIStackViews and buttons set `isUserInteractionEnabled = false`. Old hitTest fallback with nearest-button lookup removed (forwarding view handles it). TouchInsets computation loop removed. KeyboardRowStackView simplified to layout-only.

## Decisions

- **Custom methods over forwarding touchesBegan directly**: UIKit tracks touch ownership internally. Calling `button.touchesBegan()` when the forwarding view owns the touch causes spurious `touchesCancelled`. Custom `handleForwardedTouch*` methods bypass this.
- **Linear scan over spatial grid**: ~35 buttons, squared distance with no sqrt < 0.1ms. Spatial grid adds complexity for zero measurable benefit.
- **Keep original touch overrides as fallback**: Even with `isUserInteractionEnabled = false`, the original methods remain for safety. No code duplication concern — they won't fire in normal operation.
