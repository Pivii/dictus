# Phase 15.5 Plan 01: UIKit Keyboard Building Blocks Summary

**UIKit keyboard layer with 5 files: ObservableObject bridge, letter key with accent long-press, 8 special key subclasses, UIStackView container with dynamic touch insets, and UIViewRepresentable wrapper with Coordinator change detection**

## Accomplishments
- KeyboardTouchState ObservableObject bridges UIKit touch events to SwiftUI for popup preview, accent strip, and trackpad overlay
- LetterKeyButton and all 8 special key subclasses use point(inside:with:) with negative UIEdgeInsets to eliminate dead zones
- KeyboardContainerView dynamically computes touch insets in layoutSubviews so every pixel between keys resolves to a tap
- KeyboardUIView wraps the UIKit layer as UIViewRepresentable with Coordinator-based change detection avoiding unnecessary rebuilds

## Files Created/Modified
- `DictusKeyboard/Views/UIKit/KeyboardTouchState.swift` - ObservableObject bridge with @Published properties for press/accent/trackpad state
- `DictusKeyboard/Views/UIKit/LetterKeyButton.swift` - UIButton subclass with extended hit regions, accent long-press, touchDown audio/haptic
- `DictusKeyboard/Views/UIKit/SpecialKeyButtons.swift` - BaseSpecialKeyButton + ShiftKeyButton + DeleteKeyButton + SpaceKeyButton + ReturnKeyButton + GlobeKeyButton + EmojiKeyButton + LayerSwitchKeyButton + AdaptiveAccentKeyButton
- `DictusKeyboard/Views/UIKit/KeyboardContainerView.swift` - UIView with UIStackView rows, KeyboardActions struct, dynamic touch inset computation
- `DictusKeyboard/Views/UIKit/KeyboardUIView.swift` - UIViewRepresentable with Coordinator tracking row counts and shift state
- `Dictus.xcodeproj/project.pbxproj` - Added UIKit group with 5 file references and build phase entries

## Decisions Made
- BaseSpecialKeyButton shared superclass: avoids duplicating ~30 lines of common setup (background, corner radius, shadow, touchInsets, point(inside:with:)) across 8 special key subclasses
- KeyboardActions struct: consolidates all 12 action callbacks into a single struct for clean passing through the UIViewRepresentable boundary
- Coordinator tracks row counts instead of full row arrays: KeyDefinition uses UUID identifiers making array equality unreliable; count comparison correctly detects layer switches
- Touch insets in layoutSubviews: Auto Layout must resolve button positions before gap widths can be measured; layoutSubviews is the correct hook
