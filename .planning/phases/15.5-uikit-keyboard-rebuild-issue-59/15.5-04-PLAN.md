**Fix 1 -- Layer switch (BLOCKER):** In KeyboardUIView.swift, the Coordinator compares row counts to detect layer changes, but all 4 layouts (AZERTY, QWERTY, numbers, symbols) have identical dimensions (4 rows, 10 first-row keys). The fix:

1. Add a `currentLayer: KeyboardLayerType` property to KeyboardUIView (pass it from KeyboardRootView).
2. Add `var previousLayer: KeyboardLayerType = .letters` to the Coordinator.
3. In `updateUIView`, replace the row-count comparison with a direct layer comparison: `if currentLayer != coordinator.previousLayer`. When different, call `container.buildKeys(rows: rows, actions: actions)` and update `coordinator.previousLayer = currentLayer`.
4. Keep the existing shift and accent lightweight update paths unchanged.
5. In `makeUIView`, store `context.coordinator.previousLayer = currentLayer`.
6. Remove the now-unused `previousRowCount` and `previousFirstRowCount` from Coordinator.

**Fix 2 -- Invisible SF Symbol icons:** In SpecialKeyButtons.swift, BaseSpecialKeyButton.commonInit() (line 47-65) calls `addSubview(backgroundView)` then `sendSubviewToBack(backgroundView)`. When subclasses call `setImage()` in their `setupIcon()`, UIButton's internal imageView may be inserted behind the backgroundView.

The fix: Add a method `ensureImageOnTop()` to BaseSpecialKeyButton that calls `if let iv = imageView { bringSubviewToFront(iv) }`. Override `layoutSubviews()` to call `ensureImageOnTop()` after `super.layoutSubviews()` and the backgroundView frame update. This ensures imageView is always on top after any layout pass.

Why layoutSubviews and not just after setupIcon: UIButton may recreate or reorder its internal subviews during layout passes. Doing it in layoutSubviews guarantees correct z-order at render time.

**Fix 3 -- Return key context adaptation:**

1. In ReturnKeyButton (SpecialKeyButtons.swift), add a public method `updateReturnKeyType(_ type: UIReturnKeyType)` that maps the type to an appropriate label and icon:
   - `.default`, `.next` -> SF Symbol "return.left"
   - `.go` -> title "Go"
   - `.search` -> SF Symbol "magnifyingglass"
   - `.send` -> title "Send"
   - `.done` -> title "OK"
   - `.join` -> title "Join"
   - `.route` -> title "Route"
   - `.continue` -> title "Suite"
   - `.emergencyCall` -> title "SOS"
   For title-based labels: call `setImage(nil, for: .normal)` then `setTitle(text, for: .normal)`.
   For icon-based labels: call `setTitle(nil, for: .normal)` then `setImage(...)`.
   Always call `ensureImageOnTop()` after setting an image.

2. Add `var onReturnKeyType: (() -> UIReturnKeyType)? = { .default }` callback to KeyboardActions struct. This is a getter, not an event -- it returns the current returnKeyType from the proxy.

3. In KeyboardContainerView, store a reference to the ReturnKeyButton (already done as `private var returnButton: ReturnKeyButton?` -- wait, it's not stored. Actually looking at the code, the createButton method returns the button but doesn't store returnButton. Add `private var returnButton: ReturnKeyButton?` and store it in createButton for `.returnKey` case.)

4. Add `func updateReturnKeyType()` to KeyboardContainerView that calls `returnButton?.updateReturnKeyType(actions.onReturnKeyType?() ?? .default)`. Store `actions` as a property so it can be accessed later.

5. In KeyboardRootView.swift, set the `onReturnKeyType` callback in the KeyboardActions to `{ [weak controller] in controller?.textDocumentProxy.returnKeyType ?? .default }`.

6. In KeyboardUIView.updateUIView(), call `container.updateReturnKeyType()` at the end of every update (it's cheap -- just checks the proxy value and updates if changed).

**Fix 4 -- Delete haptic stops on empty text:**

1. Change `onDelete` in KeyboardActions from `() -> Void` to `() -> Bool`. The Bool indicates whether text was actually deleted.

2. In KeyboardRootView.swift, update the onDelete closure: before calling `deleteBackward()`, check `controller.textDocumentProxy.documentContextBeforeInput`. If nil or empty, return false. Otherwise call `deleteBackward()` and return true. Same for the autocorrect undo path (always returns true since it's undoing existing text).

3. In DeleteKeyButton (SpecialKeyButtons.swift), change `onDelete` from `(() -> Void)?` to `(() -> Bool)?`. In the touchesBegan immediate delete, call `let deleted = onDelete?() ?? false`. In the repeat loop, call `let deleted = self.onDelete?() ?? false`. If `!deleted`, skip the haptic and audio, and break the loop.

4. Keep onWordDelete as `() -> Void` (word delete always has text to delete if reached).
