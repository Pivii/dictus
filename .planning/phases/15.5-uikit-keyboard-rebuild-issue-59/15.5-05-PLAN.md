**Fix 1 -- Dead zones in side padding and between UIStackView gaps:**

The mainStack is inset by `KeyMetrics.rowSidePadding` (3-5pt) from the container edges. Touches in that padding zone hit no button because the UIStackView chain never forwards them. The fix: override `hitTest(_:with:)` on KeyboardContainerView to catch missed touches and route them to the nearest button.

In KeyboardContainerView.swift:

1. Add a flat array property `private var allButtons: [UIView] = []` populated in `buildKeys()` -- collect all created buttons (both LetterKeyButton and BaseSpecialKeyButton subclasses) into this array.

2. Override hitTest:
```swift
override func hitTest(_ point: CGPoint, with event: UIEvent?) -> UIView? {
    // First, try the normal hit-test chain (UIStackView routing)
    if let hit = super.hitTest(point, with: event) {
        return hit
    }
    // If normal chain missed (touch in side padding or sub-pixel gaps),
    // find the nearest button by distance to its center
    guard bounds.contains(point) else { return nil }
    var bestButton: UIView?
    var bestDistance: CGFloat = .greatestFiniteMagnitude
    for button in allButtons {
        let center = button.superview!.convert(button.center, to: self)
        let dx = point.x - center.x
        let dy = point.y - center.y
        let dist = dx * dx + dy * dy  // squared distance (skip sqrt for perf)
        if dist < bestDistance {
            bestDistance = dist
            bestButton = button
        }
    }
    return bestButton
}
```

This catches the 3-5pt side padding dead zones and any sub-pixel rounding gaps.

3. In `buildKeys()`, after the loop that creates buttons, populate `allButtons` from the created buttons. Reset it at the top with `allButtons.removeAll()`. Add each created button: `if let button = createButton(for: key, actions: actions) { rowStack.addArrangedSubview(button); createdButtons.append((button, key)); allButtons.append(button) }`.

**Fix 3 -- Popup clipping on first row:**

In KeyboardRootView.swift, the popup overlay is inside a ZStack with `.frame(height: keyboardHeight)`. First-row key popups go above Y=0 and get clipped.

The fix: Move ONLY the popup/accent overlays to a separate `.overlay` on the ZStack. Keep the trackpad overlay inside the ZStack (it fills the keyboard area). SwiftUI `.overlay` content is NOT clipped to the parent's frame -- it renders outside the bounds.

Final layout structure:

```swift
ZStack(alignment: .top) {
    KeyboardUIView(...).frame(height: keyboardHeight)

    // Trackpad overlay stays inside (fills keyboard area)
    if touchState.isTrackpadActive {
        Color(.systemBackground).opacity(0.6)
            .cornerRadius(8)
            .allowsHitTesting(false)
            .transition(.opacity)
    }
}
.overlay(alignment: .topLeading) {
    // Key popup -- outside ZStack frame, won't clip on first row
    if let label = touchState.pressedKeyLabel, !touchState.showingAccents {
        KeyPopup(label: label)
            .position(x: touchState.pressedKeyFrame.midX,
                      y: touchState.pressedKeyFrame.minY - 28)
            .allowsHitTesting(false)
    }

    // Accent popup -- with edge clamping
    if touchState.showingAccents {
        let accentCount = CGFloat(touchState.accentOptions.count)
        let totalWidth = accentCount * 36
        let halfWidth = totalWidth / 2
        let kbWidth = touchState.keyboardWidth
        let rawX = touchState.accentKeyFrame.midX
        let clampedX = max(halfWidth, min(rawX, kbWidth - halfWidth))

        AccentPopup(accents: touchState.accentOptions,
                    selectedIndex: touchState.selectedAccentIndex)
            .position(x: clampedX,
                      y: touchState.accentKeyFrame.minY - 28)
            .allowsHitTesting(false)
    }
}
```

The Y offset of -28 places the popup so the stem tip touches the key's top edge (bubble height 56/2 = 28, stem extends below).

```swift
let totalWidth = CGFloat(accentCount) * accentCellWidth
let kbWidth = touchState?.keyboardWidth ?? bounds.width * 10  // fallback: no clamping
let frameInKB = frameInKeyboardCoordinateSpace()
let rawMidX = frameInKB.midX
let halfWidth = totalWidth / 2
let clampedMidX = max(halfWidth, min(rawMidX, kbWidth - halfWidth))

// Convert clamped position back to button-local coordinates

let index = Int((location.x - popupStartX) / accentCellWidth)
```

**Fix 5 -- Emoji picker clipping:**

The emoji picker bypasses KeyboardContainerView's rowSidePadding and has minimal internal padding. The hosting view respects safe area insets from the UIInputView parent.

1. In EmojiPickerView.swift, add `.padding(.horizontal, KeyMetrics.rowSidePadding + 4)` to the outer VStack body. The +4 accounts for the safe area inset that UIInputView applies.

2. In EmojiCategoryBar.swift, add `.padding(.horizontal, KeyMetrics.rowSidePadding + 4)` to the outer HStack.

3. Add `.padding(.top, 4)` to the EmojiPickerView body VStack if not already present (ensures category title "SMILEYS" is not clipped at top).

Since both files are in the same module (DictusKeyboard), no import needed -- just use `KeyMetrics.rowSidePadding` directly.
